# Sistema de iglesia Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implementar la consulta de cuerpos recuperados, su resurrección pagada, su entierro con honores y el memorial histórico de caídos.

**Architecture:** Se ampliará el servicio funcional `servicios/iglesia.py`, sin dependencias de Tkinter ni de JSON. Las consultas y operaciones recibirán `TypedDict` ya validados; validarán todas las precondiciones antes de mutar el estado, igual que `servicios/reclutamiento.py`. Un cálculo puro pequeño en `servicios/calculos.py` fijará el descuento y permitirá probar el redondeo independientemente de los valores actuales del catálogo.

**Tech Stack:** Python 3.11+, anotaciones de tipo nativas, `TypedDict`, `unittest`, JSON existente solo como frontera futura.

**Spec:** `docs/superpowers/specs/2026-11-07-iglesia-design.md`

## Global Constraints

- Mantener el diseño funcional elegido; no crear una clase `Iglesia`.
- Mantener servicios independientes de Tkinter, `input()`, `print()` y archivos JSON.
- El coste será el 70% de la contratación equivalente y se redondeará hacia abajo.
- Los muertos recuperados siguen en `datos_activos` y ocupan cupo.
- Resucitar conserva ID, nombre, plantilla, nivel y experiencia.
- Enterrar no cuesta dinero, libera cupo y agrega el motivo `enterrado_con_honores`.
- Validar todas las condiciones antes de realizar la primera mutación observable.
- Usar documentación interna completa y tipos explícitos en las funciones públicas.

## Review Focus

- Un ID con espacios o minúsculas debe localizar el mismo `AV-0001`; se prueba en la tarea 1.
- Un ID existente que pertenece a un vivo debe producir un error distinto de un ID inexistente; se prueba en la tarea 1.
- Un coste cuyo 70% no sea entero debe redondearse hacia abajo; se prueba en la tarea 1 con coste `11 -> 7`.
- Una resurrección sin dinero suficiente no debe modificar ni dinero ni aventurero; se prueba en la tarea 2.
- El memorial debe conservar el orden histórico y excluir `servicios_finalizados`; se prueba en la tarea 3.
